# 情境：提案與商務說服

適用於顧問提案、報價單、專案企劃書、內部立案申請、募資簡報——**產出物是要讓對方做出一個帶有承諾的決定。**

這是所有情境裡 Objective 最單純的一種：對方看完之後要**簽約／核准／投錢**。也因為目標明確，這個情境最容易踩到相反的陷阱——為了說服而過度承諾。

## 這個情境的五維重心

| 維度 | 在這類任務裡特別重要的原因 |
|---|---|
| **S** | 客戶的產業、規模、預算與時程期待，決定了整份提案的可行性邊界 |
| **C** | 顧問的專業定位決定提案的說服路徑——策略型、執行型、數據型會寫出三種提案 |
| **O** | 罕見地直接是一個行為（簽約），而不是認知改變。這讓取捨變得非常清楚 |
| **R** | 提案的段落順序就是說服的節奏。現況分析在前，是為了讓解決方案有立足點 |
| **E** | **核心是防過度承諾。**「所有承諾都要可被驗證」是這個情境最有價值的一條限制 |

**這個情境有一個獨特的判準：每一句承諾，三個月後能不能拿出證據說做到了？**「提升品牌能見度」做不到驗證，「三個月內在指定三個通路各產出 12 篇內容，並提供每篇的觸及與互動數據」可以。這條判準同時服務了兩件事——讓提案更可信，也讓自己不會被自己的提案坑死。

## 問答選項設計要點

**情境那題**要問出預算、時程與客戶的成熟度，這三個變數決定提案的規模：

- A（推薦）品牌轉型中的中小企業，預算 30 萬，希望三個月內看到具體成果
- B 已有內部行銷團隊的中型企業，找外部顧問補特定缺口
- C 剛起步的品牌，預算有限但願意長期合作，重點在建立基礎

**角色那題**拉出不同的說服路徑：

- A（推薦）經驗豐富的內容策略顧問，擅長把抽象需求轉化成具體服務
- B 數據導向的成長顧問，用指標與預估回報說話
- C 產業資深操盤手，用過往案例與同業對標建立信任

**限制那題**的核心是可驗證性與語氣的翻譯：

- A（推薦）語氣專業有溫度，避免行銷術語，所有承諾都要可被驗證
- B 高度數據化，每個主張都附預估數字與計算依據
- C 極簡一頁式，只講三件事：解決什麼、怎麼做、多少錢

## 完整範例

### 原始需求
> 幫我寫一份提案給客戶

### SCORE 拆解

| 維度 | 內容 |
|---|---|
| **S** 情境 | 客戶是品牌轉型中的中小企業，預算 30 萬，希望三個月內看到具體成果 |
| **C** 角色 | 經驗豐富的內容策略顧問，擅長把抽象需求轉化成具體服務 |
| **O** 目標 | 讓客戶看完提案後就決定簽約 |
| **R** 產出 | 提案大綱：現況分析、解決方案、執行時程、成果指標、報價結構 |
| **E** 限制 | 語氣專業有溫度，避免行銷術語，所有承諾都要可被驗證 |

### 成品 Prompt

```
## 情境
客戶是一家正在做品牌轉型的中小企業，預算 30 萬，希望在三個月內看到具體成果。他們過去沒有和外部顧問合作的經驗，對「成果」的定義還很模糊，這正是提案要幫他們釐清的事。

## 你的角色
你是一位經驗豐富的內容策略顧問，最擅長的事情是把客戶說不清楚的抽象需求，轉化成具體、有邊界、可以驗收的服務項目。你講話專業但不端架子，會誠實說出哪些事三個月做不到。

## 任務目標
這份提案要達成一件事：讓客戶看完之後決定簽約。

這代表兩個判準——客戶要覺得「這個人懂我的問題」（所以現況分析必須具體到像是看過他們的東西），以及「這個方案我付得起也等得起」（所以時程與報價必須對得上 30 萬與三個月）。任何無助於這兩件事的內容都刪掉。

## 輸出要求
產出提案大綱，依序包含五個部分：
1. **現況分析** — 客戶目前的處境與核心問題，用他們自己會認同的語言描述
2. **解決方案** — 具體的服務項目，每項說明做什麼、交付什麼
3. **執行時程** — 三個月的分階段規劃，每階段有明確的產出
4. **成果指標** — 怎麼判斷這次合作成功了，指標必須可測量
5. **報價結構** — 30 萬如何拆分到各項服務與各階段

## 限制條件
- 語氣專業但有溫度：用「我們」而非「本公司」，可以有第一人稱的判斷（「我建議先從 X 開始，因為……」），但不要出現熱情洋溢的推銷語
- 避免行銷術語。不使用「賦能」「痛點」「一站式」「全方位」「深度賦權」這類詞，改用白話描述實際做的事
- **每一項承諾都必須可被驗證**：三個月後能拿出證據說做到了。「提升品牌能見度」不合格，「在指定三個通路各產出 12 篇內容並提供觸及數據」合格
- 誠實標示邊界：三個月做不到的事直接說明「這一階段不包含」，不要用模糊語言帶過
- 報價的每一項都要對應到解決方案裡的具體服務項目，總額不得超過 30 萬
```

### 自檢

- ✅ **Objective ≠ Result**：O 是「客戶決定簽約」這個行為，R 是五段式提案大綱
- ✅ **Character 有作用**：換成「數據導向的成長顧問」，整份提案會改用指標與預估回報說話，說服路徑完全不同
- ⚠️ **Situation 有資訊量**：預算、時程、客戶沒有外部合作經驗都是有效的外部事實，最後一點直接改變了現況分析的寫法。但缺客戶所屬產業——現況分析要「具體到像看過他們的東西」，沒有產業與現有素材資訊，模型只能寫出通用診斷。補上產業、現有通路、目前的內容長什麼樣，這一段會有量級差異
- ✅ **Result 有骨架**：五個部分，且順序本身服務於說服節奏
- ⚠️ **Exactness 可驗證**：「專業有溫度」原本不可驗證，已翻譯成三條可檢查的規則（用「我們」而非「本公司」、可有第一人稱判斷、不出現推銷語）。若你心中的「溫度」還有別的具體樣貌，補進去會更準
- ⚠️ **五維無矛盾**：O 要「看完就簽約」、E 要「所有承諾可驗證」，兩者輕微拉扯——最有說服力的話往往最難驗證。這裡選擇讓可驗證性優先，代價是提案讀起來比一般提案克制。若你需要更有溫度的版本，放寬的方式是允許在現況分析段有主觀判斷，但解決方案與成果指標段維持可驗證

## 這個情境的常見陷阱

**「讓客戶簽約」看起來像廢話，其實是最有用的 Objective。**因為它可以直接推導出取捨標準：客戶要覺得「你懂我」以及「我付得起」。把這兩個判準寫進 prompt，模型就知道哪些內容該留、哪些是自我陶醉。

**語氣形容詞必須翻譯。**「專業有溫度」是使用者心裡有畫面但模型抓不到的典型。不要照抄進限制條件，要問或翻譯成可檢查的規則：人稱怎麼用、能不能有主觀判斷、哪些語氣詞禁用。這是 `rules/quality-check.md` 驗收測試的直接應用。

**行銷術語要列舉，不能只說「避免」。**「賦能」「痛點」「一站式」「全方位」——把實際想禁的詞列出來，比寫十次「不要用行銷術語」有效，因為模型對「什麼算行銷術語」的認定跟使用者未必一致。

**可驗證性條款保護的是提案者自己。**過度承諾在提案階段最好寫，在交付階段最難還。強制「每項承諾三個月後拿得出證據」這條，等於在寫提案時就做了一次風險審查。這是這個情境裡最值得堅持的一條限制。

**報價要對應到具體服務項目。**「策略規劃 10 萬」客戶無從判斷貴不貴；「策略規劃：含競品盤點報告一份、三個月內容主軸定義、通路配置建議書，10 萬」才有討論基礎。報價的顆粒度直接影響成交率。
