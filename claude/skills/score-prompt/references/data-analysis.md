# 情境：資料分析與決策支援

適用於銷售分析、營運報表、A/B 測試解讀、成效歸因——**產出物是要拿去支撐某個決定的東西。**

## 這個情境的五維重心

| 維度 | 在這類任務裡特別重要的原因 |
|---|---|
| **S** | 業務背景決定什麼數字算異常。營收下滑 12% 是災難還是季節性，取決於情境 |
| **C** | 決定分析的深度與語言——分析師、顧問、統計學家會產出三種不同的東西 |
| **O** | **這個情境最關鍵的一維。**分析要支撐哪個決策，決定了要看哪些切面 |
| **R** | 要指定「發現的數量」與「每個發現的欄位」，否則會拿到一大堆平鋪直敘的觀察 |
| **E** | 重心在**防杜撰**：不准提出資料無法支撐的推論，這是分析類任務最大的風險 |

**最容易寫壞的一維是 O，而且是所有情境裡最嚴重的。**使用者說「我要一份分析報告」——那是 Result。沒有 Objective 的分析會變成資料的流水帳：每個維度都切一遍、每張圖都畫一張，然後沒有任何一頁回答「所以我該怎麼做」。

## 問答選項設計要點

**目標那題是這個情境的重頭戲**，選項必須是三個不同的決策，而不是三種報告形式：

- A（推薦）決定下季要把行銷預算押在哪些通路
- B 向董事會說明本月未達標的原因
- C 找出哪些 SKU 應該停產

三個選項會導向完全不同的分析：A 要看通路的邊際效益，B 要看與預測的差異歸因，C 要看單品的獲利與庫存週轉。同一批資料，三種截然不同的切法。

如果使用者三個都不選、說「都要」，那是三份分析，該分三次做——這件事值得當場說清楚。

**限制那題**的核心是防杜撰與受眾語言：

- A（推薦）每個發現必須引用具體數字；不提出無法用現有數據驗證的推論；不使用統計術語
- B 允許提出假設，但假設必須標記為「待驗證」並說明如何驗證
- C 需附上每個結論的計算方式與資料來源欄位，供他人覆核

## 完整範例

### 原始需求
> 幫我分析一下上個月的銷售數據

### SCORE 拆解

| 維度 | 內容 |
|---|---|
| **S** 情境 | 電商公司，月營收約 2000 萬，通路為官網與三個電商平台；上月營收較前月下滑 12% |
| **C** 角色 | 在零售業做過五年的資料分析師，擅長把數字翻譯成經營層聽得懂的行動建議 |
| **O** 目標 | 支撐「下季行銷預算要押在哪些通路」這個決策 |
| **R** 產出 | 一頁式摘要：三個關鍵發現、每個發現的數據依據、一段預算配置建議 |
| **E** 限制 | 每個發現必須引用具體數字；不提出無法用現有數據驗證的推論；不使用統計術語 |

### 成品 Prompt

```
## 情境
我們是一家電商公司，月營收約 2000 萬，銷售通路是官網加上三個電商平台。上個月營收較前月下滑 12%，但我們還不確定是通路問題、品類問題，還是單純的季節性。

## 你的角色
你是一位在零售業做過五年的資料分析師，擅長把數字翻譯成經營層聽得懂的行動建議，而不是堆砌圖表。你的習慣是先確認資料能回答什麼、不能回答什麼，再開始下結論。

## 任務目標
這份分析要支撐一個具體決策：下一季的行銷預算應該押在哪些通路。所有分析都要指向這個問題——與這個決策無關的有趣觀察，請略過或放到最後一句帶過。

## 輸出要求
產出一頁式摘要，包含：
1. 三個關鍵發現 — 每個發現一句話講結論，後接數據依據
2. 每個發現背後的數據依據 — 引用具體數字與比較基準
3. 一段預算配置建議 — 明確說出建議加碼哪裡、縮減哪裡、理由是什麼

## 限制條件
- 每個發現都必須引用具體數字，並說明比較基準（與上月？與去年同期？與其他通路？）
- 不提出無法用現有數據驗證的推論。資料不足以支撐某個判斷時，直接說明「這需要 X 資料才能確認」，不要用推測填補
- 不使用統計術語（p 值、信賴區間、顯著性等），對象是非技術背景的經營層
- 發現數量固定為三個。如果資料只支撐得起兩個紮實的發現，就寫兩個並說明原因，不要湊數
```

### 自檢

- ✅ **Objective ≠ Result**：O 是支撐通路預算決策，R 是一頁式摘要，兩者明確分離
- ✅ **Exactness 可驗證**：「引用具體數字」「不用統計術語」「發現數量」都可逐句檢查
- ✅ **Character 有作用**：換成「學術統計學家」會產出完全不同的東西
- ✅ **Situation 有資訊量**：營收量級、通路結構、下滑幅度都是外部事實
- ⚠️ **Result 有骨架（但未指定視覺化）**：三個發現的結構清楚，不過若需要圖表應補明「附幾張圖、什麼類型」，否則模型可能全用文字
- ⚠️ **五維無矛盾**：「固定三個發現」與「資料不足時不湊數」略有張力，我在限制條件裡已寫明衝突時以不湊數優先

## 這個情境的常見陷阱

**沒有 Objective 的分析必然變成流水帳。**如果使用者說不出這份分析要支撐什麼決策，那是一個值得當場點出的訊號——很可能他真正需要的不是分析，而是一份定期監控的 dashboard。

**防杜撰的限制不能省。**分析類任務裡，模型最危險的行為是把「資料沒說的事」寫得像結論。務必有一條類似「資料不足時直接說明缺什麼，不要用推測填補」的限制，並且要求標註比較基準——沒有基準的百分比是最容易誤導人的東西。

**指定發現的數量，但要留退路。**「三個關鍵發現」逼模型做取捨，避免平鋪直敘；但同時要允許「資料只支撐兩個就寫兩個」，否則它會為了湊數而編出第三個。這兩條要一起寫。
