# 搜尋自動完成

## 概述

使用者在商店搜尋框輸入時，即時跳出建議字詞，降低打錯字與想不到關鍵字造成的搜尋失敗。

## 背景與問題

目前搜尋框沒有任何提示，站內搜尋有 34% 的查詢回傳零結果，其中多數是拼字錯誤或使用了非商品用語。零結果查詢的跳出率是有結果查詢的 3 倍。

## 目標

- 零結果搜尋比例從 34% 降到 15% 以下
- 建議清單在使用者停止輸入後感覺是「即時」出現的

## 非目標（範圍外）

- 不做個人化建議（不依使用者歷史排序）
- 不做語意搜尋／同義詞擴展
- 不改動搜尋結果頁本身的排序邏輯

## 使用者與情境

- **作為** 站上訪客，**我想要** 打字時看到候選字詞，**以便** 不用自己想出正確的商品名稱

## 功能需求

| 編號 | 優先級 | 需求描述 |
|------|--------|----------|
| FR-1 | P0 | 使用者在搜尋框輸入 2 個字元以上時，顯示建議清單 |
| FR-2 | P0 | 建議清單最多顯示 8 筆 |
| FR-3 | P0 | 可用鍵盤上下鍵在建議間移動，Enter 選取，Esc 關閉 |
| FR-4 | P1 | 輸入快速變動時，只呈現最後一次輸入對應的結果（不得出現過期回應覆蓋新結果） |
| FR-5 | P2 | 建議項目中命中的輸入片段以粗體標示 |

## 非功能需求

- **效能**：建議清單需在 200ms 內回應
- **可用性 / 無障礙**：需符合 combobox 的鍵盤與螢幕閱讀器行為
- **i18n**：需同時支援中文與英文輸入

## 驗收標準

- [ ] FR-1：Given 搜尋框聚焦，When 輸入 2 個字元，Then 出現建議清單
- [ ] FR-2：Given 後端回傳 20 筆建議，When 清單顯示，Then 只呈現 8 筆
- [ ] FR-3：Given 建議清單開啟，When 按下向下鍵再按 Enter，Then 以該建議發起搜尋
- [ ] FR-4：Given 連續快速輸入，When 較早的請求較晚回來，Then 畫面呈現的是最後一次輸入的結果

## 相依與風險

- **相依**：後端 `/api/search/suggest` 端點（已存在，回傳字串陣列）
- **風險**：每次按鍵都打 API 會放大後端負載 → 需要節流
